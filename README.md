# C Drive Space Watch

Windows 本地磁盘空间快照与差异分析工具。第一版重点解决：**保存目录快照 → 任意选择两次快照 → 像资源管理器一样逐层查看哪些文件/文件夹变大或变小**。

## 技术架构

- 后端：Go，负责目录递归扫描、目录大小汇总、差异计算、Windows 文件夹选择器。
- 数据库：SQLite（`data/spacewatch.db`），适合几十万/上百万文件条目的索引和局部查询。
- 前端：Vue 3 + TypeScript + Vite。
- 配置：`config/config.json`。
- 快照与配置均保存在项目/发布目录内，不写入注册表和用户 AppData。
- 后端会强制排除自身 `data/` 目录，避免扫描时把不断增长的 SQLite 数据库统计进快照。

## 已实现

- 默认扫描目录 `C:\Users`，可在设置中修改，也可每次创建快照时单独选择目录。
- Windows 原生目录选择对话框；同时允许直接输入路径。
- 快照异步扫描，UI 可继续操作。
- 默认只保存目录记录；仍会递归读取文件并计算每个目录的总大小、后代文件数量和变化指纹。开启“记录文件数据”后，才会额外保存每个文件的路径、大小和修改时间。
- Windows 默认按 `Size on disk`（实际磁盘占用）统计，而不是只看逻辑文件大小；可在设置中关闭。
- 跳过无法访问的项目、符号链接/重解析点，并记录跳过数量。
- 任意选择两个已完成快照进行比较。
- 比较结果支持新增 / 删除 / 变化 / 未变化状态。
- 每个目录保存递归指纹；即使目录总大小刚好不变，但内部发生了“一个文件增大、另一个文件减小”等抵消变化，目录仍会标记为“变化”，可以继续双击下钻。
- 文件夹大小直接显示 A、B 和 `B-A` 差值。
- 双击文件夹进入下一级，面包屑导航返回任意上级目录。
- 当前目录搜索、排序、隐藏/显示未变化项。
- 快照根目录不同也可按相对路径比较，并显示提示。
- 删除快照时级联删除其索引数据。
- SQLite WAL 模式，数据库索引按 `snapshot_id + parent_rel` 查询，前端不会一次加载整棵文件树；不再维护未使用的按文件大小索引，减少快照写入量。

## 放置位置建议

如果主要监控 C 盘，建议直接把整个 `c-drive-space-watch` / 发布版 `dist` 放在 **D 盘或其他非 C 盘**。快照数据库本身会随快照数量增长，放在 D 盘可以避免监控工具反过来消耗 C 盘空间。

## 开发运行

环境：Windows、Go、Node.js/npm。

双击：

```text
dev.bat
```

首次会安装前端依赖，然后启动：

- Go API: `http://127.0.0.1:8899`
- Vue Dev Server: `http://127.0.0.1:5173`

## 构建发布版

双击：

```text
build.bat
```

构建产物位于 `dist/`：

```text
dist/
├─ SpaceWatch.exe
├─ start.bat
├─ web/               # Vue 静态文件
├─ config/config.json
└─ data/              # SQLite 数据库会创建在这里
```

进入 `dist` 后双击 `start.bat` 即可。

重新构建时会保留 `dist/data/spacewatch.db` 和已有的 `dist/config/config.json`，不会清空历史快照或覆盖运行时配置。

如果 `frontend/node_modules` 已存在，`build.bat` 会跳过前端依赖安装；Go 构建也不会再单独执行 `go mod download`，而是直接使用本机模块缓存，缺少依赖时才通过配置的 Go 代理下载。

## 数据结构

SQLite 主要有两张表：

- `snapshots`: 一条记录代表一次扫描，保存根目录、创建时间、总大小、文件数、目录数、状态等。
- `entries`: 每个快照的目录索引，以及在开启“记录文件数据”时追加的文件索引；`rel_path` 使用相对于扫描根目录的路径，使不同时间甚至不同根目录的快照也可以比较。

默认关闭文件数据记录可以显著降低数据库体积。关闭时快照仍然会读取文件并把文件大小、数量和修改信息汇总到目录层，因此目录级空间变化比较仍然可用；文件级新增、删除和变化需要开启设置并重新创建快照。

目录不是在比较时临时递归求和，而是在创建快照时已经计算并落库，因此进入某个目录进行比较时只查询该层的直接子项，性能更稳定。

## 当前边界

- “移动/重命名”在第一版中表现为旧路径删除 + 新路径新增，不做内容哈希级重命名识别。
- 为了保证快照扫描速度，默认不计算文件哈希；比较依据路径、类型、实际占用大小、修改时间以及目录聚合大小/文件数。
- 如果要完整扫描 `C:\`，建议以管理员权限运行，否则 Windows 系统保护目录会被跳过。
- 当前快照扫描任务不能在扫描过程中取消；可在下一版增加取消、暂停和计划任务。
